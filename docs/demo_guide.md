# 操作手册：两个页面怎么用

服务启动后浏览器访问 `http://<board-ip>:8080`。所有操作都在网页上完成，板卡上只剩实体按键。

---

## 1. 素材评测页（`/`）

目标：**用一段现场视频，把六项功能的 ARM 与 FPGA 都测一遍，并给出该走哪个通道的建议。**

### 1.1 步骤

| 步 | 操作 | 预期 |
|---|---|---|
| 1 | 点「上传现场视频」选一段本地视频 | 显示文件名与时长；开始自动抽帧 |
| 2 | 系统自动抽同一组帧，对**平滑 / 边缘提取 / 锐化**各跑 ARM 与 FPGA | 右侧出现三种效果的两侧耗时的 P95、逐像素误差 |
| 3 | 在「当前画面通道」里切 ARM / FPGA，在效果按钮里切三种效果 | 预览图随之变化；`视频信息` 显示帧号、FPS、滤波耗时、丢帧 |
| 4 | 系统自动从这段视频抽取音轨，对**低通 / 高通 / 带通**各跑 ARM 与 FPGA | 音频区显示三种频段的耗时与逐样本误差 |
| 5 | 「波形模式」下拉切低通 / 高通 / 带通 | 画布上同图叠加三路波形：原始（灰）、ARM（蓝）、FPGA（绿） |
| 6 | 看「六项处理方案推荐」表 | 每项给出推荐通道与依据（实测误差 + P95 耗时） |
| 7 | 需要改判就改六个下拉框 | 下拉框里 FPGA 选项在"该功能 FPGA 不可用或误差非 0"时自动禁用 |
| 8 | 点「确认方案并进入实时监控」 | 跳转 `/monitor`，六项选择成为监控页的初始配置 |

### 1.2 推荐规则（网页上也是这么写的）

1. **误差不为 0** → 该功能不给 FPGA 选项，只推 ARM。
2. 误差为 0 时比 **P95 耗时**：FPGA 更快则推 FPGA，更慢则推 ARM。
3. 推荐理由一行写清依据（哪个数字、哪个口径），不留"推荐使用 FPGA"这种空话。

因此同一段素材可能出现"边缘、锐化走 FPGA，平滑走 ARM"的混合结论——这是允许的，也是本作品想表达的东西。

## 2. 实时监控页（`/monitor`）

目标：**现场采一段音视频，实时跑双通道处理，画面同时上网页和 HDMI，声音从板卡音频口出来。**

### 2.1 选择采集源

| 采集源 | 前置条件 | 说明 |
|---|---|---|
| 板载 USB 摄像头 + USB 麦克风 | 摄像头/麦克风插在板卡 USB 主机口；`arecord -l` 能看到设备 | 点「启动板载采集」，数据不出板卡，时延最低 |
| 电脑浏览器摄像头 + 麦克风 | 电脑上运行 `host/deploy/tools/camera_proxy.py`（或 `host/deploy/tools/start_camera_proxy.bat`） | 浏览器把 JPEG（≤512 KB）与 PCM 块（≤8192 样本）POST 给板卡，适合没有板载 USB 设备的场合 |

摄像头代理启动方式：

```text
python host/deploy/tools/camera_proxy.py --board http://<board-ip>:8080
```

代理窗口必须保持运行；浏览器要用 `http://localhost:8765/monitor` 打开（浏览器只对 localhost 放开摄像头权限）。

### 2.2 运行与观察

| 观察项 | 位置 |
|---|---|
| 处理画面 | 网页中部的实时预览（JPEG，质量 75） |
| HDMI 输出 | 外接显示器，640×360 画布放大到 1280×720，左右同屏（原图 / 处理结果） |
| 处理后声音 | 板载 3.5 mm 音频口，由硬件 FIFO 按 48 kHz 推进 |
| 波形 | 网页波形区（原始 / 滤波后两路，4096 点环形历史） |
| 运行状态 | 帧号、FPS、每帧滤波耗时、累计帧数、丢帧数、音频已播采样数、欠载计数 |
| 通道与效果 | 下拉框在线切换；切换模式时音频走 960 样本交叉淡化，不出爆音 |

### 2.3 板载按键

| 按键 | 功能 |
|---|---|
| BTN0 | 低通 800 Hz |
| BTN1 | 高通 3000 Hz |
| BTN2 | 带通 800–2500 Hz |
| BTN3 | 素材评测页：切换 ARM / FPGA 通道；监控运行时：切换 HDMI 画面 / 音频分析视图 |

开始、停止、改效果、改通道都在网页上；按键只做现场快捷操作。

## 3. 常见问题

| 现象 | 原因与处置 |
|---|---|
| 页面显示"板卡连接中断" | 板端 8080 服务未启动或网络不通；先确认 `%run` 的日志里有 `ready on port 8080` |
| 摄像头代理报 403 | 浏览器必须用 `localhost` / `127.0.0.1` 打开，不能用电脑局域网 IP |
| 摄像头代理报 502 | `--board` 地址填错，或板卡 8080 未启动 |
| 有画面无声音 | 页面「电脑扬声器」是否开着、系统是否静音；首次启动后浏览器可能再次询问音频权限 |
| 声音断续 | 先关闭网页扬声器看波形是否连续，再看 Wi-Fi / CPU 占用，或板卡是否同时在跑其他 DMA 任务 |
| HDMI 无画面但 `/api/status` 显示 `output_active` | 板端只能证明逻辑在输出，不能证明显示器锁到信号；换线 / 换显示器 / 重载 overlay 后再判断 |
| 帧率只有 7–8 FPS | 属正常：整条链路还受解码、合成与 HDMI 刷新限制，滤波本身只占其中一段（口径见 `metrics/metrics.csv`） |
| 音频欠载计数不为 0 | 说明 PL 消耗快于供给，检查是否同时在跑视频传输（共用一条 DMA，靠锁串行化） |
