# 系统架构与数据流

## 1. 总体架构

```text
                     ┌─────────────────────────── 上位机 / 手机浏览器 ───────────────────────────┐
                     │  素材评测页 /        实时监控页 /monitor         （HTML + JS，无框架）      │
                     └───────────────────────────────┬──────────────────────────────────────────┘
                                                     │ HTTP :8080（同一局域网）
┌────────────────────────────────────────────────────┴─────────────────────────────────────────────┐
│ PYNQ-Z2（XC7Z020）                                                                                │
│                                                                                                  │
│  ┌──────────────────────── ARM PS（Cortex-A9 ×2，Linux / PYNQ 3.1）────────────────────────┐   │
│  │  Python HTTP 服务  console_app → integrated_app → video_app                                │   │
│  │      ├─ 视频：解码 → 缩放 320×240 → 3×3 滤波 → 合成 640×360 → JPEG 预览 / HDMI 画布        │   │
│  │      ├─ 音频：PCM16 分块 → 255 抽头 FIR → 960 样本交叉淡化 → 写入硬件 FIFO                 │   │
│  │      ├─ 测量：单滤波调用 / 完整播放分轮 / 音频后端基准                                     │   │
│  │      └─ 采集：UVC 摄像头（V4L2）/ USB 麦克风（ALSA）                                        │   │
│  │  软件后端：OpenCV 3×3 与 reference.c（gcc -O3 现场编译）＝ 唯一数值标准                     │   │
│  └───────────────┬──────────────────────────────────────────────────┬───────────────────────┘   │
│                  │ AXI-Lite 控制字 / 寄存器读写                      │ UIO / mmap 帧缓冲          │
│  ┌───────────────┴──────────────── FPGA PL（100 MHz）───────────────┴───────────────────────┐   │
│  │  video_smooth_router.v   同一条 AXI-Stream 上按控制字切换：                                │   │
│  │      [31]=0 音频旁路（S_AXIS→AUDIO_IN，AUDIO_OUT→M_AXIS）                                  │   │
│  │      [31]=1 视频 3×3 滤波，[21:20] 选 平滑 / 边缘 / 锐化 / 原画                            │   │
│  │  audio_fir（HLS）        255 抽头 4 路 MAC、256 样本环形历史、Q1.15 定点                   │   │
│  │  axi_dma                  音频块与视频帧**分时复用同一条 DMA**（板端同一把锁保护）           │   │
│  │  audio_fifo_arch.vhd     8192 样本播放 FIFO，按 48 kHz 帧率消耗，欠载计数与签名 0x53414631   │   │
│  │  hdmi_framebuffer.v      640×360 RGB332 双缓冲 → rgb2dvi → 1280×720@60                      │   │
│  └───────────────┬───────────────────────────────────────────────┬────────────────────────────┘   │
│                  │ UVC / ALSA（USB 主机口）                        │ HDMI OUT（rgb2dvi）           │
└──────────────────┼───────────────────────────────────────────────┼────────────────────────────────┘
                   │                                               │
            USB 摄像头 + USB 麦克风                        HDMI 显示器（720p60）
            （传感器：画面 / 声音）                        （执行器：对照画面）
```

**传感器 / 执行器 / 通信链路**

| 角色 | 器件 | 挂接方式 |
|---|---|---|
| 传感器 | UVC 摄像头（代码注释中的实测型号：Hikvision DE-UVC12 类复合设备） | USB 主机口 → V4L2 / OpenCV |
| 传感器 | USB 麦克风（或板载 HP MIC） | USB → ALSA `arecord`，重采样到 48 kHz |
| 执行器 | HDMI 显示器 | PL 的 `hdmi_framebuffer` → `rgb2dvi` → HDMI OUT |
| 执行器 | 板载 3.5 mm 音频口 | PL 的播放 FIFO → 板载 audio codec |
| 执行器 | 网页 | 板端 `video_app` 的 HTTP 路由 |
| 通信 | 以太网（板卡 ↔ 上位机） | HTTP :8080，JSON + multipart + JPEG 流 |
| 通信 | AXI-Lite / AXI-Stream / AXI-DMA | PS ↔ PL，控制字与数据搬运 |

## 2. 数据流

### 2.1 素材评测（上传视频）

```text
上传视频 ─┬─ 画面分支：解码 ─→ 抽同一组帧 ─→ 缩放到 ≤320×240 ─┬─ ARM：OpenCV 3×3 ────────┐
          │                                                    └─ FPGA：填充 w+2,h+2 → 打包 → DMA → router → 回拷 → 解包 ┤
          │                                                                                        ├─→ 合成 640×360 画布 → JPEG 预览
          │                                                                                        └─→ 逐像素与 ARM 比对（误差作为"方案建议"的硬门槛）
          └─ 音轨分支：抽取 PCM16 48 kHz ─→ 低通/高通/带通 ─┬─ ARM：reference.c ──────────────┐
                                                            └─ FPGA：DMA → audio_fir → DMA ──┤
                                                                                             ├─→ 三路波形同图对比
                                                                                             └─→ 逐样本误差与耗时 → 六项通道建议
```

建议规则：**误差不为 0 的功能不给 FPGA 选项；误差为 0 时按 P95 耗时给推荐**，
比值 <1（FPGA 更慢）时明确建议走 ARM——不美化结论。

### 2.2 实时监控（摄像头 + 麦克风）

```text
UVC 帧 ─→ 缩放到处理区 ─→ 3×3 滤波（ARM 或 FPGA）─→ 合成 640×360 画布 ─┬─→ JPEG（质量 75）→ 网页预览
                                                                      └─→ 写入 RGB332 双缓冲 → HDMI 720p60
ALSA PCM 块（≤8192 样本）─→ 255 抽头 FIR（ARM 或 FPGA）─→ 960 样本交叉淡化 ─→ 硬件 FIFO ─→ 板载音频口
                                    │
                                    └─→ 滤波后采样追加到 4096 点环形历史 → 网页波形
```

### 2.3 音画同步（完整播放）

```text
音频是主时钟：FIFO 每消耗一个 48 kHz 采样帧，已播采样计数 +1
视频侧每渲染一帧前读一次"已播采样"，据此决定是否跳过迟到的帧
欠载（FIFO 空）立即记录并终止会话 → 会话时长与采样数可对账，不靠 sleep 近似
```

## 3. 软硬件划分依据

| 准则 | 落到具体决策 |
|---|---|
| **数值一致性优先** | ARM 侧 `reference.c` 与 OpenCV 实现是唯一标准；FPGA 只负责"按同一契约算出同样的数"，因此边界填充放在 ARM，RTL 不处理越界 |
| **同一资源上分时复用** | 音频块与视频帧共用一条 AXI DMA，靠 `video_smooth_router` 的 `[31]` 位在"音频旁路"与"视频滤波"之间切换；板端用同一把锁保护整段传输 |
| **按项目决定归属，不按口号** | 边缘提取（32.2 → 11.5 ms）与锐化（15.5 → 11.7 ms）走 FPGA；平滑（7.7 → 11.6 ms）与原画（0.56 → 11.6 ms）走 ARM |
| **时间基准放到硬件** | 音频播放由 8192 样本 FIFO 的 48 kHz 帧率推进，避免 CPU 调度抖动导致时长与欠载无法证明 |
| **显示路径硬件化** | HDMI 扫描输出做成 PL 的双缓冲 + rgb2dvi，ARM 只负责写画布，不参与像素时序 |
| **能力上限用契约表达** | 视频处理区 320×240；更大的静态图片用 318×238 核心 + 1 像素真实 halo 分块，不降分辨率、不让 ARM 代做滤波 |

**为什么不能只用软件替代 PL 部分**

- 视频像素时序与 720p60 扫描输出需要确定性节拍，ARM 上做不到无抖动的像素时钟输出。
- 音频播放需要硬件采样计数作为同步基准；纯软件定时无法给出可对账的"已播采样数"。
- 完整播放实测：滤波走 FPGA 时整板 CPU 从 64.5% 降到 59.1%（见 `metrics/metrics.csv`），
  说明滤波确实从 CPU 上移走了；这是"能不能替代"的直接证据，而不是核内周期数。

## 4. 状态与异常处理

| 场景 | 处理 |
|---|---|
| AXI DMA 复位/启动失败 | 有界轮询 + 超时返回错误状态，打印错误码，不无限等待 |
| 音频 FIFO 欠载 | 记录欠载计数并终止当次会话，会话结束给出 submitted / played / seconds / expected 对账行 |
| 视频渲染来不及时 | 按已播采样跳帧并累计 `dropped`，不阻塞音频 |
| 上传体积超限 | 视频 100 MB、监控帧 512 KB、监控音频块 8192 样本，超限直接拒绝并回错误 |
| Overlay 与板卡不配套 | `check_hardware.py` 在加载前拒绝未修正辅助复位极性的 HWH |
| HDMI 无信号 | 板端只能报告 `output_active`，物理链路未远程确认（已列入已知边界） |
