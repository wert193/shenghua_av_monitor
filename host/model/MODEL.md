# 算法与数值精度（对应赛题"模型来源与精度"一项）

## 1. 先说清楚：本作品不使用机器学习模型

赛题 3.2.5.1(3) 要求"模型来源与版本、数值精度或量化方式、推理后端及其配置"。
本作品**没有 AI 模型、没有推理框架、没有权重文件**，因此该项在本仓库中**不适用**。
替代它的是一套**确定性定点 DSP 算法**，其"模型文件"就是滤波器系数与卷积核常量：

| 赛题要求项 | 本作品的对应物 | 位置 |
|---|---|---|
| 模型来源与版本 | 系数由本仓库脚本按既定公式生成，可逐位复现（无外部权重） | `fpga/src/scripts/generate_coeffs.py` → `fpga/src/hls/coefficients.h` |
| 数值精度 / 量化方式 | 音频 **Q1.15**（系数 ×32768 取整、`int32` 累加、最后一次舍入饱和）；视频 **8 位无符号 + 16 位中间量** | 见第 2、3 节 |
| 推理后端及其配置 | **无推理后端**；两个计算后端是 ARM Cortex-A9（OpenCV / `reference.c`）与 FPGA PL（HLS IP + RTL 流水） | `host/app/`、`fpga/src/hls/`、`fpga/src/rtl/` |

**为什么选确定性 DSP 而不是 AI 推理**（这也是被放弃的候选方案）：

| 候选方案 | 放弃原因 |
|---|---|
| 在 PL 上跑 CNN（DPU / Vitis AI） | XC7Z020 的 DSP 与 BRAM 余量不足：本作品已占 138/140 BRAM Tile，再放卷积加速器需要外挂 DDR 帧缓存与重新划分存储结构；且工业现场需要的是"看得更清、听得更准"，不是分类 |
| 在 ARM 上跑 ONNX 推理 | 双核 A9 无 NEON 定点加速收益，单帧推理时延远超 3×3 滤波，与"实时监控"目标冲突 |
| 远端服务器推理 | 引入网络时延与可用性依赖，工业现场不可接受；且本作品要回答的是"同一算法该放 ARM 还是 FPGA"，与模型无关 |

选择确定性滤波的收益是可验证：**同一输入下两个后端的结果必须逐像素 / 逐样本为 0 误差**，
这比"模型准确率"更适合作为异构算力对照的证据。不同工况的自适应由"通道择优"承担，
而不是靠模型重训。

## 2. 音频：255 抽头线性相位 FIR

### 2.1 系数

| 项 | 值 |
|---|---|
| 抽头数 | 255（系数表按 256 存储，末位补零） |
| 窗函数 | Hamming |
| 量化 | Q1.15：`coef_q15 = round(h[n] × 32768)`，有符号 18 位 ROM |
| 群延时 | 127 样本（模式 3 用它做"原曲延时对齐"） |
| 采样率 | 48 kHz 标称、PCM16 单声道 |

四种模式：

| 模式 | 通带 | 构造方式 |
|---|---|---|
| 0 低通 | ≤ 800 Hz | 直接设计 |
| 1 高通 | ≥ 3000 Hz | 由低通做谱反转（系数符号交替）构造 |
| 2 带通 | 800–2500 Hz | 低通差分构造 |
| 3 原样延时 | 全通 | 仅 127 样本延时，用于与线性相位通路的时延对齐 |

### 2.2 舍入与饱和契约（ARM 与 FPGA 必须完全一致）

```text
累加：sum = Σ (x[n-k] × coef[k])          // int32，全程不舍入
输出：y   = (sum + 16384) / 32768          // 最后一次舍入（四舍五入）
饱和：y   = clamp(y, -32768, 32767)        // 再饱和回 PCM16
历史：256 样本环形缓冲，跨调用保持；clear_history 置 1 时清零
分块：块间状态连续，块边界不重置历史（模式在一次交易内固定）
```

参考实现：ARM 侧 `fpga/src/board/reference.c`（`gcc -O3 -shared -fPIC` 现场编译）；
FPGA 侧 `fpga/src/hls/fir_kernel.cpp`（4 路 MAC 并行）。两者共用同一套 Q1.15 系数。

### 2.3 模式切换的瞬态

切换用 **960 样本（约 20 ms）线性交叉淡化**；过渡途中再次切换从当前混合值出发，
不跳变、不出爆音。淡化在板端完成，IP 内部不参与。

## 3. 视频：3×3 邻域滤波

| 效果 | 运算 | 精度与舍入 |
|---|---|---|
| 平滑 | binomial `[[1,2,1],[2,4,2],[1,2,1]]` | 16 位累加，`(sum+8)>>4` |
| 边缘提取 | 亮度 `gray=(29R+150G+77B+128)>>8`，Sobel `Gx`/`Gy` | `(|Gx|+|Gy|+2)>>2`，饱和到 255 |
| 锐化 | `5·c − t − b − l − r` | 16 位有符号，饱和到 `[0,255]` |
| 原画直通 | 不做运算 | — |

- 输入 BGR888 打包为 32 位 `R | G<<8 | B<<16`，输出同样打包，`TKEEP=4'hf`。
- **边界为复制填充，且填充在 ARM 侧完成**（输入 `w+2 × h+2`，输出 `w × h`），
  RTL 内部不处理越界，避免硬件与软件在边界策略上分叉。
- 处理区上限 320×240；更大的静态图片按 **318×238 核心 + 1 像素真实 halo** 分块，
  滤波后裁掉 halo 再拼接，不降分辨率、不让 ARM 代做滤波。
- 亮度权重取整数近似（29 / 150 / 77 之和为 256），保证 ARM 与 RTL 用同一条公式，
  逐像素误差为 0 可以做到，不需要容差。

## 4. 两个后端的等价性判定

| 判定项 | 通过条件 |
|---|---|
| 视频 | 同一输入、同一效果，ARM 与 FPGA 输出**逐像素误差 0**（4 种效果 × 24 组 RTL 用例 + 板端每模式 12 帧） |
| 音频 | 同一 PCM 块、同一模式，ARM 与 FPGA 输出**逐样本误差 0**（含符号极值、饱和、环形回卷、分块连续） |
| 数值口径 | 舍入位置（只在最后一步）、饱和位置（输出）、边界策略（复制填充）三项必须与 `reference.c` 一致 |

不一致时的定位顺序：先看边界填充是否是 `w+2,h+2` → 再看舍入是否只在最后一步 →
最后看饱和是否落在输出而不是中间量。
